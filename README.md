# منصة الفيلسوف محمود حسن

مشروع React + Vite بواجهة عربية RTL، مع Supabase للمصادقة وقاعدة البيانات وتخزين إيصالات التحويل.

## المتطلبات
- Node.js 20 أو أحدث
- حساب Supabase ومشروع جديد
- حساب Vercel للنشر (اختياري محلياً)

## إعداد Supabase
1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor وشغّل محتوى `supabase/schema.sql` كاملاً.
3. من Project Settings ثم API انسخ Project URL و anon/public key (أو publishable key المتوافق مع مشروعك).
4. سجّل حساب المدرّس من واجهة المنصة أولاً.
5. من SQL Editor نفّذ ترقية حساب المدرّس فقط إلى مدير، مع استبدال البريد:
   ```sql
   update public.profiles set role = 'admin' where email = 'TEACHER_EMAIL';
   ```
   لا تمنح دور المدير للطلاب. احتفظ بوصول SQL للمسؤول الموثوق فقط.
6. من Authentication > URL Configuration اضبط Site URL على رابط الموقع المنشور، وأضف رابط الموقع المحلي ورابط الإنتاج إلى Redirect URLs. فعّل تأكيد البريد حسب سياسة المنصة.

## تشغيل محلي
```bash
cp .env.example .env
# املأ القيم الحقيقية داخل .env
npm install
npm run dev
```

متغيرات البيئة:
- `VITE_SUPABASE_URL`: رابط مشروع Supabase.
- `VITE_SUPABASE_ANON_KEY`: مفتاح anon/public أو publishable؛ لا تستخدم service_role.
- `VITE_VODAFONE_CASH_NUMBER`: رقم محفظة التحويل الذي سيظهر للطلاب.

## النشر على Vercel
1. ارفع المشروع إلى مستودع Git خاص أو عام حسب رغبتك.
2. استورد المستودع في Vercel.
3. استخدم إعدادات البناء الافتراضية لـ Vite: Build Command `npm run build` و Output Directory `dist`.
4. أضف متغيرات البيئة الثلاثة في إعدادات المشروع على Vercel (يمكن ترك رقم المحفظة اختيارياً إذا لم تستخدم التحويل اليدوي).
5. انشر المشروع، ثم أضف نطاق Vercel إلى Supabase Authentication > URL Configuration.

## ما تم تجهيزه في هذه النسخة
- تدفق تسجيل الطلاب والدخول وتسجيل الخروج واستعادة كلمة المرور.
- ملف الطالب وقائمة اشتراكاته.
- عرض الكورسات النشطة وطلب الاشتراك ورفع الإيصال.
- قيود نوع وحجم ملف الإيصال (5 ميجابايت) على الواجهة والتخزين.
- عرض الإيصال للمدير عبر رابط موقّع مؤقت لمدة 60 ثانية.
- إضافة الكورسات والدروس ومراجعة طلبات الاشتراك من لوحة المدير.
- إعادة طلب الاشتراك بعد رفض الطلب السابق، مع منع وجود أكثر من طلب معلق أو اشتراك مفعل للكورس نفسه.
- سياسات RLS أساسية، وحماية حقل الدور من تعديل الطالب عبر صلاحيات الأعمدة.

## نقاط يجب إكمالها قبل استقبال طلاب ودفع حقيقي
- **لم يتم ربط المشروع بمشروع Supabase فعلي**؛ لا توجد بيانات اعتماد أو رقم محفظة ضمن الحزمة. يجب على مالك المنصة إدخالها بنفسه في إعدادات النشر.
- **لم يتم اختبار الاتصال الفعلي أو سياسات RLS على مشروع Supabase** لعدم توفر مشروع/مفاتيح/حسابات اختبار. يجب اختبار حساب طالب وحساب مدير منفصلين قبل الإطلاق.
- فودافون كاش هنا تحويل يدوي وإيصال للمراجعة، وليس تكاملاً مع بوابة دفع أو تأكيداً آلياً للتحويل.
- روابط الفيديو الخارجية ليست محمية بمجرد تسجيل الدخول. استخدم مزود فيديو بروابط موقعة/مؤقتة أو DRM قبل نشر محتوى مدفوع؛ لا تستخدم روابط عامة قابلة للمشاركة.
- لا توجد اختبارات آلية شاملة، ولا نظام اختبارات/درجات مكتمل رغم وجود جدول نتائج مبدئي.
- فعّل حماية البريد وكلمات المرور، واضبط رسائل البريد وسياسة الخصوصية وشروط الاستخدام والنسخ الاحتياطي ومراقبة الأخطاء.
- راجع SQL وسياسات التخزين مع مطور Supabase قبل الاستخدام الإنتاجي، واختبر صلاحيات الطالب والمدير ومحاولات الوصول غير المصرح بها.

**حالة المشروع:** ملفات المصدر جرى تجهيزها، لكن لا يصح وصف المنصة بأنها جاهزة لاستقبال مدفوعات أو بيانات طلاب حقيقية قبل إتمام الإعدادات والاختبارات المذكورة أعلاه.
